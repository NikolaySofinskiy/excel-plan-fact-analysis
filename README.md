# Excel Plan-Fact Analysis

План-факт анализ выручки в Excel по модели данных с использованием Power Query, Power Pivot, DAX и сводной таблицы.

---

## 🎯 Цель проекта

Построить интерактивный план-факт отчёт по выручке, который позволяет:

- Сравнивать **фактическую выручку** с **плановой** по месяцам.
- Видеть **отклонение** в абсолютных и относительных величинах.
- Рассчитывать **процент выполнения плана**.
- Анализировать продажи в разрезах: **город**, **товар**, **месяц**.
- Выявлять проблемные зоны (недовыполнение плана) и точки роста (перевыполнение).

Проект демонстрирует навыки построения аналитического отчёта в Excel:
загрузка и очистка данных (Power Query), построение модели данных «звезда»
(Power Pivot), написание мер на DAX, визуализация через сводные таблицы.

## 📊 Исходные данные

Данные представлены двумя независимыми источниками в формате Excel:

### 1. План продаж (`plan_revenue.xlsx`)

План представлен в **матричном (широком) формате**: месяцы — в столбцах.

| Город | Товар | Январь | Февраль | ... | Декабрь | ИТОГО |
|---|---|---|---|---|---|---|
| Москва | Футболка хлопковая | 2 066 000 | 1 655 000 | ... | 2 213 000 | 23 975 000 |
| Москва | Кроссовки беговые | 2 985 000 | 2 775 000 | ... | 2 354 000 | 27 194 000 |
| ... | ... | ... | ... | ... | ... | ... |

**Особенности:**
- Месяцы в столбцах (Январь–Декабрь).
- Строки «ИТОГО» по каждому городу.
- Объединённые ячейки по городу.
- Пустые строки-разделители между городами.

⚠️ В таком виде план **не подходит для модели данных** — требуется преобразование.

### 2. Факт продаж (`fact_revenue.xlsx`)

Факт представлен в **длинном формате**: одна строка = одна продажа.

| Дата | Товар | Город | Выручка |
|---|---|---|---|
| 01.01.2025 | Кроссовки беговые | Москва | 65 964 |
| 01.01.2025 | Джинсы классические | Москва | 94 642 |
| 01.01.2025 | Футболка хлопковая | Краснодар | 55 470 |
| ... | ... | ... | ... |

**Особенности:**
- Дата в формате `ДД.ММ.ГГГГ`.
- Период: **2025 год** (январь–декабрь).
- Один и тот же товар может встречаться несколько раз в день.
- Гранулярность — **одна транзакция**.

## 🔄 Этапы реализации

### 1. Загрузка данных
- Подключение к исходным файлам (`plan_revenue.xlsx`, `fact_revenue.xlsx`)
  через Power Query.
- Первичный осмотр структуры, типов данных, аномалий.

### 2. Обработка данных (Power Query)
`plan_revenue.xlsx`:
- Очистка: удаление пустых строк и строк «ИТОГО».
- Заполнение вниз объединённых ячеек по городу.
- Удаляем столбец ИТОГО
- Преобразование плана из **широкого формата** (месяцы в столбцах)
  в **длинный** через Unpivot.
- превращаем столбец с месяцем в тип данных дата: добавляем префикс "1 ", добавляем суффикс " 2025", меняем тип данных на "Дата",
  переименовываем столбец с "Атрибут" на "Дата".
- меняем имя запроса на c "PlanRevenue1" на "PlanRevenuePrepared"
- загружаем таблицу в модель данных Power Pivot

`fact_revenue.xlsx`:
- проверяем типы данных - все верно
- меняем имя запроса c "FactRevenue1" на "FactRevenuePrepared"
- загружаем таблицу в модель данных Power Pivot

- Добавляем таблицы измерения (справочники)
- products (копируем запрос с планом, создаем список из столбца с товарами и удаляем дубликаты, затем превращаем обратно в таблицу
  и переименовываем столбец на "Наименование")
- geography (копируем запрос с планом, создаем список из столбца с городами и удаляем дубликаты, затем превращаем обратно в таблицу
  и переименовываем столбец на "Город")

### 3. Модель данных (Power Pivot)

Создадим меры:
